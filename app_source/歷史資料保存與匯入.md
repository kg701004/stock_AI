# 歷史資料保存：完整、可驗證、體積小

## 保存策略

所有使用者資料預設放在 `D:\stock_AI`（位置可在 [storage.json](config/storage.json) 調整），程式原始碼仍留在專案資料夾。

| 層級 | 格式 | 用途 | 安全性與體積 |
|---|---|---|---|
| 原始資料 | UTF-8 CSV + gzip（`.csv.gz`） | 可重建、人工檢查、跨平台保存 | 小、開放、長期可讀 |
| 校驗 | SHA-256 | 驗證原始資料未遺失或被改動 | 極小 |
| 查詢資料庫 | SQLite | 指標、回測、篩選與分析 | 單檔、可索引、可備份 |
| 備份 | SQLite backup API 產生的副本 | 災難復原 | 不直接複製運行中的 WAL 資料庫 |

每日 OHLC 價格以整數微元（價格 × 1,000,000）寫入 SQLite，避免浮點數誤差。原始 CSV 不覆寫；相同內容以 SHA-256 去重，因此重複匯入不會讓資料膨脹。

## 匯入格式

複製 [sample_daily_bars.csv](data/sample_daily_bars.csv)，必要欄位為：

```text
symbol,date,open,high,low,close,volume,source,published_at
```

`published_at` 必須有時區，這是避免回測偷看未來資料的必要欄位。

## 指令

```powershell
python history_cli.py import data/sample_daily_bars.csv
python history_cli.py verify
python history_cli.py backup D:\stock_AI\backups\history_20260722.sqlite
```

## 建議收集年限

- 日線、成交量、指數、產業與估值：盡量取得可得的完整歷史，最低 10 年。
- 月營收、法人、融資融券：盡量完整，最低 5–10 年。
- 財報與公司事件：盡量完整，並保存最初公布時間與後續修正版本。
- 期貨、選擇權、夜盤：完整取得若可行；至少 3–5 年才能涵蓋不同波動環境。
- 系統自己的因子、權重、建議與持股結果：永久保存。

## 每月維護

1. 執行 `verify`，確認所有壓縮原始檔校驗值正確。
2. 以 `backup` 產生 SQLite 備份，將備份再複製到另一顆磁碟或可靠雲端空間。
3. 不修改既有原始檔；資料來源修正時，以新檔與新發布時間再次匯入。
